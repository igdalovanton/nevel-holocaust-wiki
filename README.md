# nevel-holocaust-wiki

Статический сайт-памятник, посвященный жертвам Холокоста в Невеле.

## Как редактировать сайт через GitHub в браузере

Эта инструкция рассчитана на студента, который не знает программирования и работает только через браузер.

### Как устроена публикация сайта

Сайт опубликован через GitHub Pages с такой настройкой:

- `Source`: `Deploy from a branch`
- `Branch`: `gh-pages`
- `Folder`: `/ (root)`

Это значит:

- опубликованный сайт берется только из ветки `gh-pages`;
- ветка `main` нужна для редактирования исходных файлов сайта;
- ветку `gh-pages` вручную редактировать не нужно.

Если вы меняете тексты, страницы или изображения, вносите изменения только в ветке `main`.

### Какие файлы можно редактировать

Редактируйте только файлы в папке `docs/`.

- `docs/index.md` - главная страница
- `docs/bluedacha.md` - страница «Голубая Дача»
- `docs/saintlikes.md` - страница о праведниках
- `docs/sources.md` - документы и медиа
- `docs/texts/` - отдельные статьи и публикации
- `docs/victims/` - страницы памяти отдельных людей

Если вам нужно просто исправить или дополнить текст, не редактируйте папки `site/`, `env/`, `scripts/`, ветку `gh-pages` и файл `mkdocs.yml`.

### Пошаговая инструкция

1. Войдите в свой аккаунт GitHub.
2. Откройте этот репозиторий в браузере.
3. Убедитесь, что вы находитесь в ветке `main`, а не `gh-pages`.
4. Перейдите в папку `docs/` и найдите нужный файл.
5. Откройте файл и нажмите кнопку с иконкой карандаша `Edit this file`.
6. Исправьте текст прямо в окне браузера.
7. Если хотите проверить результат, откройте вкладку `Preview`.
8. Пролистайте страницу вниз до блока сохранения.
9. В коротком описании напишите, что именно изменили, например: `Исправлен текст на главной странице`.
10. Нажмите `Commit changes...`.
11. Если GitHub предложит выбор:

- `Commit directly to the main branch` - если у вас есть право сразу сохранять изменения в `main`.
- `Create a new branch and start a pull request` - если GitHub не разрешает менять `main` напрямую. В этом случае нажмите `Propose changes`, затем создайте `Pull Request`.

### Как добавить изображение

Изображения нужно загружать в папку `docs/images/`.

Простой и безопасный вариант:

1. Откройте в GitHub папку `docs/images/`.
2. Зайдите в подходящую подпапку, например `pages/` или создайте новую папку.
3. Нажмите `Add file` -> `Upload files`.
4. Перетащите изображение в окно браузера.
5. Нажмите `Commit changes`.

После этого откройте нужный текстовый файл в `docs/` и вставьте ссылку на картинку.

### Пример: добавить одну картинку

Если файл страницы лежит в папке `docs/`, а изображение загружено в `docs/images/pages/photo.jpg`, можно вставить такой код:

```md
![Подпись к изображению](images/pages/photo.jpg)
```

Если страница лежит глубже, например в папке `docs/texts/`, путь будет другим:

```md
![Подпись к изображению](../images/pages/photo.jpg)
```

### Пример: картинка с подписью

```html
<figure style="margin: 0; text-align: center;">
  <img src="../images/pages/photo.jpg" alt="Описание изображения" style="width: 100%; height: auto; border-radius: 8px;">
  <figcaption><em>Подпись под изображением</em></figcaption>
</figure>
```

### Пример: несколько изображений таблицей или галереей

На странице [bluedacha.md](/Users/antonigdalov/nevel-holocaust-wiki/memorial-wiki/docs/bluedacha.md) используется блок с несколькими изображениями в виде аккуратной галереи. Можно взять этот шаблон и заменить пути и подписи:

```html
<div style="display: grid; grid-template-columns: repeat(2, minmax(0, 1fr)); gap: 24px; align-items: start;">
  <figure style="margin: 0; text-align: center;">
    <img src="../images/pages/photo1.jpg" alt="Описание 1" style="width: 100%; height: auto; border-radius: 8px;">
    <figcaption><em>Подпись 1</em></figcaption>
  </figure>
  <figure style="margin: 0; text-align: center;">
    <img src="../images/pages/photo2.jpg" alt="Описание 2" style="width: 100%; height: auto; border-radius: 8px;">
    <figcaption><em>Подпись 2</em></figcaption>
  </figure>
</div>
```

Если нужна именно простая таблица из двух картинок, можно использовать такой вариант:

```md
| Фото 1 | Фото 2 |
| --- | --- |
| ![Фото 1](../images/pages/photo1.jpg) | ![Фото 2](../images/pages/photo2.jpg) |
```

### Как понять, какой путь к картинке писать

- если редактируете файл прямо в `docs/`, пишите путь от `images/...`
- если редактируете файл в `docs/texts/` или `docs/victims/`, обычно нужно писать `../images/...`

Перед сохранением всегда проверяйте вкладку `Preview`.

### Самые простые правила оформления текста

- Пустая строка создает новый абзац.
- Строка с `#` в начале - это заголовок.
- Строка с `-` в начале - это пункт списка.
- Ссылка записывается так: `[текст ссылки](https://...)`.

### Что важно помнить

- Не переименовывайте файл, если вам нужно только исправить текст.
- Не удаляйте символы `#`, `[]`, `()` и другие служебные знаки, если не уверены, зачем они нужны.
- Все содержательные изменения нужно вносить только в ветке `main`.
- Ветку `gh-pages` вручную редактировать не нужно.
- Папка `site/` создается автоматически. Основные правки нужно вносить в `docs/`.
- Если нужно добавить новую страницу, новую фотографию или поменять структуру меню, лучше обратиться к администратору проекта.
- Изменения в GitHub не всегда сразу появляются на опубликованном сайте. Если сайт не обновился автоматически, сообщите об этом человеку, который отвечает за публикацию.
